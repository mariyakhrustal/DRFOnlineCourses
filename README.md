# Проект - DRFOnlineCourses

## Описание

Платформа для онлайн-обучения, LMS-системы, в которой каждый желающий может размещать свои полезные материалы или курсы.
Данный проект представляет собой API для платформы онлайн-курсов, с поддержкой отложенных задач и периодических
рассылок.
Проект полностью контейнеризирован с помощью Docker.

## Требования

* Python 3.12 / Django / DRF
* PostgreSQL (База данных)
* Redis (Брокер сообщений)
* Celery & Celery Beat (Фоновые и периодические задачи)
* Docker & Docker Compose (Контейнеризация)

## Установка:

- Клонируйте репозиторий:

```
git clone git@github.com:mariyakhrustal/DRFOnlineCourses.git
```

- Установите зависимости:

```
pip install -r requirements.txt
```

## Инструкция по запуску

### 1. Настройка переменных окружения

Создайте в корне проекта файл `.env` и заполните его, используя в качестве примера файл `.env_sample`.

**Обратите внимание на настройки для Docker:**

* `CELERY_BROKER_URL=redis://redis:6379/0`
* `CELERY_RESULT_BACKEND=redis://redis:6379/0`

### 2. Сборка и запуск контейнеров

Запустите проект одной командой:

```
docker-compose up --build -d
```

Эта команда соберет образы и запустит все сервисы в фоновом режиме.
После запуска веб-приложение будет доступно по адресу: `http://localhost:8000`.

### 3. Проверка работоспособности сервисов

Для проверки статуса всех контейнеров выполните:

```
docker-compose ps
```

### 4. Для просмотра логов всех контейнеров

```
docker-compose logs
```

### 5. Для остановки сервисов и удаления контейнеров:

```
docker-compose down
```

## Настройка удаленного сервера и деплой

В проекте настроен автоматический деплой через GitHub Actions. При каждом push запускается цепочка (Workflow),
которая тестирует, собирает и обновляет проект на сервере.

### Настройка удаленного сервера

Для успешного деплоя на сервере должны быть:

- ОС: Ubuntu.
- Docker и Docker Compose.
- Созданная папка проекта (путь по умолчанию: ~/myapp).

### Настройка GitHub Secrets

Для работы Workflow необходимо добавить следующие переменные в Settings -> Secrets and variables -> Actions:

* SSH_KEY - Ваш приватный SSH ключ для доступа к серверу
* SERVER_IP - IP адрес вашего сервера
* SSH_USER - Имя пользователя на сервере (например, root)
* DOCKER_HUB_USERNAME - Логин на Docker Hub
* DOCKER_HUB_ACCESS_TOKEN - Токен доступа Docker Hub
* SECRET_KEY - Django Secret Key
* DB_NAME / DB_USER / DB_PASSWORD - Данные для подключения к PostgreSQL

### Процесс деплоя (Workflow)

Автоматизация разделена на три этапа:

1. Test: Запуск тестов Django.
2. Build: Сборка Docker-образа и отправка его в Docker Hub.
3. Deploy: * Копирование конфигураций (включая nginx.conf и docker-compose.yml) на сервер.
    - Генерация файла .env из секретов GitHub.
    - Перезапуск контейнеров командой docker compose up -d --build.

### Ручное управление на сервере

1. Просмотр логов
   `docker compose logs`
2. Перезапуск проекта
   `docker compose up -d --build`
